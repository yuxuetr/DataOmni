## 安装与首次启动

目前没有预编译安装包，要从源码构建，步骤见 README 的「从源码构建」。

- **macOS**：应用没有签名和公证，第一次打开会被拦下。到「系统设置 → 隐私与安全性」
  里放行一次即可。
- **Linux**：要保存密码，需要一个已解锁的 Secret Service（GNOME 桌面自带
  gnome-keyring）。没有也能用，只是不能勾「将密码保存到系统凭据库」，每次连接时
  输入密码。钥匙串是在应用运行中才装上的话，要重启 DataOmni 才认得到。

启动后看到的是欢迎页：已保存的连接列在中间，下面是「新建连接」和
「打开 SQLite 文件…」。

## 界面一览

```
┌──────────────┬──────────────────────────────────────────┐
│ 连接选择器   │ 标签栏  [查询 · xxx] [库.表] [+] [📂] [↺] │
├──────────────┼──────────────────────────────────────────┤
│ 数据库浏览器 │                                          │
│  筛选对象…   │        当前标签的内容                    │
│  ▾ 表 (12)   │   （SQL 编辑器 / 表数据 / 结构 / ER 图） │
│  ▸ 视图 (3)  │                                          │
│              │                                          │
├──────────────┤                                          │
│ 外观 语言    │                                          │
│ 查询历史     │                                          │
│ 设置         │                                  [任务] │
└──────────────┴──────────────────────────────────────────┘
```

- **左侧栏**：最上面是连接选择器，下面是当前连接的对象树，底部是外观、语言、
  「查询历史」和「设置」。⌘B 折叠或展开整个侧边栏；侧边栏右边缘可以拖宽，
  双击恢复默认宽度。
- **标签栏**：每个查询、每张打开的表、结构页和 ER 图各占一个标签。
  `+` 新建查询标签，📂 打开一个 `.sql` 文件，↺ 重新打开最近关闭的标签。
- **右下角**：导入导出这类后台任务在跑时出现一个任务面板。
- **⌘K** 打开命令面板：输入几个字就能找到连接、表，或者执行「新建查询标签」
  「打开 SQLite 文件」「切换外观」这类操作。

标签和 SQL 草稿会随应用关闭保存，下次打开原样恢复。**查询结果不保存**，
恢复后要重新执行。

## 连接数据库

### 新建连接

点欢迎页或连接选择器里的「新建连接」，打开「新建数据库连接」表单。

| 字段 | 说明 |
| --- | --- |
| 连接名称 | 只给自己看，列表和标签上显示它 |
| 环境 | 开发 / 测试 / 预发 / 生产。见下面的[环境](#环境) |
| 数据库类型 | MySQL、PostgreSQL、SQLite、SQL Server，以及 MariaDB、TiDB、CockroachDB。其余几种是计划中的，置灰选不了 |
| 主机地址、端口 | 数据库服务器的地址。端口按类型自动填默认值 |
| 数据库名称 | 连上之后默认进入的库。MySQL 必须填：对象树、补全和 ER 图都按这个库读 |
| 用户名、密码 | 数据库账号 |
| 将密码保存到系统凭据库 | 默认勾上。取消后密码只在这次运行中有效，重启后要重新输入 |
| TLS 模式 | 仅 MySQL / PostgreSQL。见下面的 [TLS](#tls) |
| 通过 SSH 隧道连接 | 数据库只在内网能访问时用。见 [SSH 隧道](#ssh-隧道) |

填完先点「测试连接」，通过后「保存连接」。之后在欢迎页或连接选择器里点这个
连接就会连上。

**MariaDB、TiDB、CockroachDB** 各有一个入口，选了会填好它自己的默认端口（TiDB 是
4000，CockroachDB 是 26257）和默认库，TLS 设成「优先使用 TLS」。它们走的是
MySQL / PostgreSQL 协议，连上之后的用法和 MySQL / PostgreSQL 一样。TiDB 与
CockroachDB 那两格标着「有缺口」，选中时表单里会列出具体哪几项用不了；完整的
对照见 README 的「兼容性矩阵」。

**SQL Server** 的功能和 MySQL / PostgreSQL 一样齐：连接（TLS、SSH 隧道）、执行、
对象树与表结构、ER 图、表格编辑、事务、执行计划、改结构与建表、CSV 导入、整表导出。
和另外几家用起来不同的几处：

- 从 SSMS 拷来的脚本可以直接跑：单独一行的 `GO` 是分批的记号，有 `GO` 时只按它切，
  每一批原样发出去——`CREATE PROCEDURE` 的过程体里有分号也没关系。没有 `GO` 时照旧
  按分号切。`GO 5`（把一批跑五遍）不认，会原样发给服务端并报错。
- 执行计划只有估算的那一种（服务端只编译不执行），「真的执行一遍」在 SQL Server 上
  是灰的。

- 默认 TLS 是「优先使用 TLS」：SQL Server 装好就带自签证书，这一档加密但不校验。
  要校验证书，选后两档并填 CA 证书路径（SQL Server 不支持客户端证书）。
- 结果里有 `sql_variant` 或 CLR 类型（geography、hierarchyid）的列时驱动读不了，
  报错里会给出写法：在查询里 `CAST(... AS nvarchar(...))` 再取。
- SQL Server 默认的读是**加锁读**，不像 MySQL / PostgreSQL 那样读旧版本：编辑器里
  开着一个改过某些行的事务（或关了自动提交还没提交）时，在表格里提交对这些行的
  改动、或者结构页去读一张还没提交的改动过的表，会等锁，等 5 秒后报
  「Lock request time out period exceeded」（1222）。回到编辑器提交或回滚即可。
  表数据页本身和编辑器走同一条会话，看得见这个事务里还没提交的改动。
- 事务状态是向服务端问的（`@@TRANCOUNT`）：有些错误（比如类型转换失败）会让
  SQL Server 自己把整个事务回滚掉，状态栏会随之回到「无事务」，而不是继续显示
  「事务中」。
- CSV 导入时，转不成目标列类型的值（`abc` 进 int 列、`2024-13-45` 进 date 列）在
  插入之前就被挑出来记成坏行：SQL Server 碰到这类错误会把整个事务回滚，没法像别家
  那样只退回这一批。万一还有别的错误让服务端回滚了导入的事务，导入会停下并说明，
  不会在没有事务的情况下接着写。

**Oracle** 在分阶段接入：能连接（服务名、SSH 隧道）、执行 SQL、浏览对象树（按
schema 分组，包归在「过程」里）、表结构（建表语句由 `DBMS_METADATA` 给出）、ER 图、
翻看表数据、补全与格式化、在表格里改数据、事务控制。执行计划、改表结构与新建表、
CSV 导入、整表导出这一版还没有，对应的按钮不出现。另外几点：

- 「数据库」那一格填的是**服务名**（Easy Connect），例如 `FREEPDB1`、`ORCLPDB1`；按 SID
  连接还不支持。TLS 要用钱包，这一版也不支持——需要加密就走 SSH 隧道。
- Oracle 没有 `BEGIN`：事务随第一条修改数据的语句开始。自动提交开着时，每条修改
  执行成功就提交；关掉之后要自己按「提交」或「回滚」。「开始事务」发的是
  `SET TRANSACTION READ WRITE`，开始之后即使自动提交还开着，也不会替你逐条提交。
  建表、改表这类 DDL 会先把当前事务提交掉，状态栏随之回到「无事务」。
- Oracle 把空字符串当成 NULL：在表格里把一格清空，存进去的是 NULL。
- 编辑器里的 PL/SQL 块照 SQL*Plus 的写法：块里的分号不切，块以单独一行的 `/` 结束。
- 应用里带着 Oracle Instant Client（Basic Light），不用另外安装。Linux 上需要系统库
  `libaio`（deb 包会自动装上）。从源码运行时先执行 `scripts/fetch-oracle-client.sh`。
- 超时与「取消」会真的让服务端停下那条语句（`DBMS_SESSION.SLEEP` 例外）。

### 打开 SQLite 文件

欢迎页或命令面板里的「打开 SQLite 文件…」直接选一个 `.db` / `.sqlite` /
`.sqlite3` / `.db3` 文件，应用会自动建一个以文件名命名的连接并连上。同一个文件
再打开不会重复建连接。

也可以在表单里选 SQLite 手动填路径。路径留空或填 `:memory:` 是内存数据库，
关掉应用内容就没了。

### 密码存在哪里

密码存进系统钥匙串（macOS 钥匙串、Windows 凭据管理器、Linux Secret Service），
配置文件里只有一个指向它的引用，不存明文。

macOS 上如果看到「系统钥匙串拒绝了访问」，通常是这条密码由另一个版本的应用写入
（自己构建的开发版每次重建签名身份都会变）。在「编辑连接」里重新输入并保存密码
即可。

### 环境

环境决定两件事：

- **常驻标识**：「生产」连接显示红色的「生产」标签，「预发」显示黄色的「预发」，
  在连接列表、工作台头部和表数据页上都有。开发和测试不标——每个连接都挂牌子
  就等于没有牌子。
- **危险语句确认的门槛**：每个环境各有一档，在「设置 → 危险语句确认」里调。
  见[危险语句确认](#危险语句确认)。

新建的连接默认是开发环境。连生产库的连接，建的时候就把环境选成「生产」。

### TLS

| 模式 | 含义 |
| --- | --- |
| 禁用 | 不加密 |
| 优先使用 TLS | 服务端支持就加密，不支持就明文 |
| 要求 TLS | 必须加密，但不校验证书 |
| 校验证书颁发机构 | 加密，并校验证书是否由受信任的 CA 签发 |
| 校验证书和主机名 | 在上一档基础上还校验证书里的主机名 |

用自签 CA 时在「CA 证书路径」里填 CA 文件。服务端要求客户端证书时，
「客户端证书路径」和「客户端私钥路径」必须**同时**填。这两项是数据库的 TLS
证书，和 SSH 私钥无关。

### SSH 隧道

数据库只在内网监听、要先登一台跳板机时，勾「通过 SSH 隧道连接」：

1. 填跳板机地址、SSH 端口（默认 22）和 SSH 用户名。
2. 选登录方式：
   - **私钥**：填私钥文件路径。私钥有口令的，把口令填在「私钥口令」里。
   - **口令**：填 SSH 登录口令。
3. 「转发到的主机」和「端口」是**从跳板机看**数据库在哪。留空就用上面填的连接
   地址；数据库就跑在跳板机上时填 `127.0.0.1`。

私钥口令和登录口令都存进系统钥匙串。以后编辑连接时这一格留空，就继续用钥匙串里
那一份；填了就替换。

跳板机的主机密钥按 `~/.ssh/known_hosts` 校验，和命令行 `ssh` 读的是同一份。
没有记录，或者记录对不上，都会拒绝连接，而且没有「跳过校验」的开关。第一次连
一台新跳板机前，先在终端里 `ssh` 上去一次，核对指纹后把它加进 known_hosts。

不支持的：`~/.ssh/config`、ssh-agent、多级跳板、证书型主机密钥。

### 连不上的时候

表单里「网络诊断」会一段一段地查，告诉你断在哪：

- **主机名解析不出地址**：拼写错了，或者这台机器的 DNS 查不到它（内网域名在
  公网 DNS 下查不到）。
- **端口没有接受连接**：服务没在跑、端口填错，或者被防火墙 / 安全组挡了。
- **端口接受了连接又立刻断开**：多半是本机开着 TUN 模式的代理，或者这个端口上
  跑的不是数据库。
- **网络这一段没有问题**：那原因就在账号密码、TLS 设置或库名上。

SQLite 查的是文件：路径读不到、是个目录、是空文件（会当成新库）、还是开头不是
SQLite 文件头（多半选错了文件）。

### 管理连接

- **编辑 / 删除**：展开左上角的连接选择器，每个连接右边有编辑和删除按钮。
- **连接信息**：工作台头部的「信息」，列出地址、库、用户、TLS、环境等。
- **断开连接**：工作台头部的「断开连接」。有没提交的事务时会先问你提交还是回滚。
- 连接断了（网络断开、服务端重启），头部会显示「连接已断开」，点「重新连接」。

## 浏览数据库对象

连上之后，左侧的「数据库浏览器」按类型分组列出表、视图、物化视图、函数、存储过程
和序列。PostgreSQL 多一层 schema。

- **单击**一张表或视图打开它的数据。
- **右键**一个对象：表有「打开数据」「打开结构」；视图有「打开数据」「查看定义」；
  函数、存储过程和序列有「查看定义」。都有「复制限定名」（带 schema 与正确引号的
  名字）。
- **筛选对象…**：输入名字的一部分，分组标题上的数字就是命中数。库里对象很多时
  用它找，别滚动：每组最多只画 200 个，其余的会提示「输入筛选继续找」。
- **键盘**：点进树之后用 ↑↓ 移动、→← 展开和收起，回车或空格打开。
- 对象列表会缓存 5 分钟，过期后自动在后台重新读。在别处建了表想马上看到，
  点头部的刷新按钮。在本应用里执行的 DDL 会自动刷新，不用手动点。

## 写 SQL 与执行

### 查询标签

- 新建：标签栏的 `+`，或命令面板的「新建查询标签」。
- **⌘S** 把当前标签的 SQL 存成 `.sql` 文件；标签栏 📂 打开一个 `.sql` 到新标签。
- 标签右键：固定标签、复制标签、关闭标签。
- **⌘W** 关闭当前标签（macOS 上 ⇧⌘W 关闭窗口）。标签里有没存过的草稿时会问：
  「丢弃」永久删除，「保留草稿」关掉标签但草稿留在最近关闭里。
- **⇧⌘T** 重新打开最近关闭的标签，最多记 10 个。
- 查询标签绑定创建它时的那个连接。连接切走或被删除后，标签只读显示草稿，不会改到
  别的连接上去执行。

### 执行

| 操作 | 按钮 | 快捷键 |
| --- | --- | --- |
| 执行光标所在的那条语句 | 执行当前 | ⌘⏎ |
| 按顺序执行全部语句，遇到失败、超时或取消即停 | 执行全部 | ⇧⌘⏎ |
| 只执行选中的文字 | 执行选中 | — |
| 停止正在执行的语句 | 停止 | — |

多条语句用分号分隔。拆分认得字符串、注释和 PostgreSQL 的 `$$` 块里的分号，不会
在那里切断。「自动解析」开着时，工具栏会显示解析出了几条语句，每条可以单独
重新执行或删除。

工具栏上的两个上限：

- **结果上限**：100、500、1,000、5,000 或 10,000 行。超出的部分截掉，结果上方会
  明确写「已达到 N 行上限，结果已截断」。要完整结果，用导出里的「完整结果」
  （见[导出](#导出)）。
- **超时**：5 秒到 5 分钟。超时的语句会被中止，报出用了多久。

### 补全、格式化与查找

- 补全按当前连接的真实结构给出表、视图和它们的列（带类型）。写了
  `FROM orders o` 之后，`o.` 会补出 orders 的列。关键字按方言过滤。
- **⇧⌘F** 格式化 SQL：有选区只排选区。解析不了的 SQL 只报错，正文不动。
- **⌘F** 查找（可替换），**⌘G** / **⇧⌘G** 下一个 / 上一个，**⌥⌘G** 跳转到行，
  **⌘/** 行注释，**⇧⌥A** 块注释。

### 出错时

失败的语句下面会显示数据库的原话：错误码（SQLSTATE）、出错位置、详情、提示、
涉及的约束和表。PostgreSQL 给了位置时可以点「跳到出错位置」。「复制完整详情」
把这些连同语句一起复制，方便贴给别人。

### 危险语句确认

执行前会按风险给语句分级，达到当前连接所在环境的门槛就先弹框确认：

| 风险 | 例子 |
| --- | --- |
| 会丢掉数据 | `DROP`、`TRUNCATE`、`ALTER … DROP COLUMN` |
| 没有 WHERE 条件，将影响整张表 | 不带 `WHERE` 的 `UPDATE` / `DELETE` |
| 会修改数据 | 带 `WHERE` 的 `UPDATE` / `DELETE` |
| 会新增数据 | `INSERT` |

默认门槛：开发、测试、预发环境从「不带 WHERE 的写入」开始确认，生产环境从
「所有写入」开始。可以在「设置 → 危险语句确认」里按环境调，也可以设成「从不确认」。

确认框会写明目标连接，以及执行后能不能撤回（在事务里可以回滚；自动提交下执行完
就落库了；有的语句在某些数据库上不受事务保护）。**确认只是给你一次停下来的机会，
不能代替数据库权限**，真正该只读的账号要在数据库里配。

### 不能用 USE 切库

在 MySQL 类的连接上（包括 MariaDB、TiDB），编辑器里的 `USE 库名` 会被拒绝：
它会让对象树悄悄变成另一个库的内容。要换库，在连接配置里改默认数据库，或者在
SQL 里写全限定名 `库名.表名`。

## 事务

工作台头部常驻事务状态：「无事务」「事务中」（带计时）或「事务已失败」。

- **自动提交**默认开着，每条语句执行完就提交。
- 点「开始事务」开一个事务，之后的语句都在里面，最后点「提交」或「回滚」。
- 关掉「自动提交」后，编辑器里的语句会自动开在一个事务里，要自己提交或回滚。
  浏览表数据不受影响。
- 自己在编辑器里写的 `BEGIN` / `COMMIT` / `ROLLBACK` 一样算数，头部的状态跟着变。
- PostgreSQL 的事务里一条语句出错后，状态变成「事务已失败」，这时除了回滚什么都
  跑不了。
- 事务还开着时切换连接、断开或退出，会先问你「提交并继续」「回滚并继续」还是
  「留下」，而不是让数据库默默回滚掉。

## 执行计划

光标放在一条语句上，点「执行计划」。数据库返回的计划解析成一棵可以展开的树，
「原文」一栏是数据库给的原样输出。

PostgreSQL 还有「真的执行一遍」：语句会**真的执行**，换来每一步的实际行数和耗时。
估算和实际差了一个数量级以上的那一步会被标出来，这通常就是慢的原因。写语句也会
真的写进去，想安全地试，先关掉自动提交，跑完回滚。

TiDB 和 CockroachDB 不支持应用用的计划格式，点了会显示服务端的原话。

## 查询结果

### 读结果

- 点表头按这一列排序（升序 → 降序 → 取消），这里排的是**已经拿到的这些行**。
- 拖列头的右边界调列宽，双击恢复按内容自适应。
- 看不见的值有区别：`NULL`、空字符串、只有空白的文本和二进制在网格里显示得不一样，
  鼠标悬停有说明。它们在 `WHERE` 里的行为完全不同，别混为一谈。
- 大整数和小数保持精度，不会被四舍五入成 JavaScript 的浮点数。

### 选择与复制

- 点一个单元格选中它，⇧ + 点击或 ⇧ + 方向键扩成矩形选区。
- **⌘C** 复制选区（TSV，贴进表格软件就是一格一格的），**⇧⌘C** 连列名一起复制。
- **⇧Space** 选中整行，**⌥Space** 选中整列。
- 右键菜单有同样的几项。

### 在结果里直接改

只有当应用能**证明**结果的每一行对应某张表的唯一一行时，结果才能就地改：
形如 `SELECT 若干列名 FROM 单表`，并且查出了主键（或一个非空的唯一键）。
有连接、并集、分组、去重、别名或表达式列时都只读，结果上方会写明是哪一条原因。
能改时双击单元格编辑，流程和[表数据](#编辑的流程)一样。

### 快速图表

结果上方的「图表」把当前结果画成柱状图或折线图，看一眼形状。默认只画第一列数值；
勾选量级差很远的几列会提示你分开看。超过 200 个点不画，先用聚合或 `LIMIT`
收一收。

## 浏览和编辑表数据

单击对象树里的一张表，打开它的「数据」页；「Schema」页是它的结构。

### 分页、排序与筛选

- 每页 25、50、100 或 200 行，分页在数据库里做。页面上方写着按哪几列稳定分页
  （通常是主键），翻页时不会重复或漏行。
- 点表头排序、「筛选」加条件，都在数据库里执行，作用于**整张表**，不只是当前页，
  行数统计也按同样的条件。
- 筛选支持：等于、不等于、大于、大于等于、小于、小于等于、包含、开头是、结尾是、
  为 NULL、不为 NULL。多个条件之间是「并且」，改完点「应用」才生效。
  暂不支持「或者」和 `IN`。
- 「列」里可以隐藏列、冻结左侧几列、调行高（紧凑 / 标准 / 宽松）。
- 「刷新」保住筛选、排序、页码、滚动位置和选区。

### 编辑的流程

改动不会立刻写进数据库，而是先排队，最后一起提交：

1. 点一行右边的编辑按钮，这一行变成可编辑。改完点这一行的 ✓（或上方的「保存」），
   这项修改**进入待提交队列**，还没有发给数据库。
2. 「添加」新增一行，「删除」按钮删除一行，同样只是排队。
3. 表格上方出现「N 项待提交」：
   - 「预览」逐条列出哪一行、哪一列、从什么改成什么，以及真正会发出去的语句。
   - 每一项可以单独「撤销」，也可以「全部撤销」。
4. 点「提交 N 项」。整批在**一个事务**里执行：任何一条失败，数据库里什么都不会变，
   待提交的改动原样留着，出错的那一条连同数据库的原因一起标出来。

改的时候，原值也会放进 `WHERE` 条件。你读到这一行之后别人又改了它，这次提交会失败
（「第 N 项没有恰好影响一行」），而不是悄悄覆盖别人的改动。刷新后再改。

主键这一列在编辑时不能改：换主键等于换了一行，请删一行再加一行。

### 每个格子写什么

每个格子左边的下拉框选**写入方式**：

| 写入方式 | 效果 |
| --- | --- |
| 值 | 写你填的内容。留空就是空字符串 |
| NULL | 写 SQL 的 `NULL`，不是空字符串 |
| 默认值 | 这一列整列省掉，由数据库套用自己的默认值。SQLite 只有新增行能选这一项 |
| 表达式 | 原样写进语句，比如 `CURRENT_TIMESTAMP` |
| 未填写 | 新增时这一列非空又没有默认值，必须填一个值才能保存 |

几种类型有专用编辑器：JSON 可以「格式化」并检查是否合法；二进制按十六进制填
（如 `de ad be ef`）；日期时间可以用选择器挑，「现在」写入 `CURRENT_TIMESTAMP`，
由数据库在执行时取值。

### 为什么这张表只读

只读的表在表格上方有一段说明，写着是下面哪种原因。

网格要靠一组能唯一定位一行的列来拼 `UPDATE` / `DELETE` 的条件：主键，或者一个
非空、完整、没有过滤条件的唯一索引。两者都没有的表只能看，改数据请在 SQL 编辑器
里写明条件。

读不到表的索引信息时（比如账号权限不够）也会只读：拿一个猜出来的键拼条件，可能
改到别的行。结构页会单独标出读不到的是哪一段。

## 表结构

「Schema」页（或右键「打开结构」）列出：

- 列：名字、类型、可空、主键、默认值。
- 索引、外键（含删除 / 更新时的动作）、检查约束、触发器。
- 定义：MySQL 与 SQLite 显示数据库给的建表语句。PostgreSQL 不提供建表语句，这里
  不拿目录拼一条可能不等价的出来，上面各段才是权威的。

某一段读不到时（比如 CockroachDB 的触发器），只有那一段显示原因，其余照常。

### 改表结构

点「编辑结构」：

- 改列名、类型、可空、默认值；「添加列」；「删除这一列」（可「撤销删除」）；改表名。
- 点「预览 SQL」，先看将要执行的全部语句，以及分开列出的「会丢掉数据」
  「这些改动做不到」（带理由）。确认后点「执行」。
- 删列会在预览里逐条点名受影响的列。

主键、索引与约束的增删改暂时不能在这里做，请用 SQL 编辑器。有几种改动明确不做：
SQLite 改列类型（要重建整张表）、MySQL 改一个默认值是表达式的列或计算列的类型
（重述出来的未必是原来那个表达式）。

TiDB 上同时改列和改表名会被整条拒绝，分两次保存即可。

### 新建表

对象树头部的 `+`：填表名、列（名字、类型、可空、默认值）并勾选主键，同样先预览
再执行。没有主键的表可以建，但建出来在网格里只能看。

## 导入 CSV

在表的「数据」页点「导入 CSV…」，三步：

1. **文件**：选文件；「第一行是列名」；分隔符默认「自动」，会告诉你认出来的是什么；
   「NULL 写成」决定文件里什么样的字段当 NULL。下面预览前几行。
2. **字段映射**：CSV 的每一列对应表的哪一列。按列名自动配对，配不上的留空，
   **不按位置猜**；不要的选「不导入」。由数据库产生的列（如自增主键）不能写。
3. **策略与执行**：
   - 批量大小：一条 `INSERT` 里放几行。
   - 事务策略：「整份一个事务」要么全进要么一行没有；「每批一个事务」出错时前面
     提交过的批次留在库里。
   - 遇到错误行：「停下」在第一条被拒的行停住；「跳过并继续」记下来接着导。

开始前的「导入前检查」分两档：一定会失败的（比如必填列没映射）直接拦住；可能不对的
（比如某个值不像这一列的类型）只提醒。

点「开始导入」后对话框关闭，导入在右下角的后台任务里跑，可以暂停、继续和取消。
失败的行按**文件里的行号**列出来，连同原始字段值。暂停时事务一直开着，别人看不到
这些行，也可能挡住对这张表的其他写入，别停太久。

## 导出

结果和表数据上方的「导出」。格式 CSV 或 JSON；CSV 可选分隔符、是否写表头、NULL
写成什么，以及「UTF-8 加 BOM」（要用 Excel 打开中文就勾上）。对话框里的预览就是文件
的真实内容。

范围：

| 在哪里 | 范围 | 导出什么 |
| --- | --- | --- |
| 表数据 | 当前页 | 屏幕上这一页，当前显示的列 |
| 表数据 | 整张表 | 全部行，按当前的筛选与排序，从数据库直接流式写进文件 |
| 表数据 / 结果 | 选中的部分 | 选中的那一块矩形 |
| 查询结果 | 当前结果 | 已经拿到的这些行（可能被结果上限截断过） |
| 查询结果 | 完整结果 | 重新执行一遍查询，不受结果上限截断；次序由 SQL 自己的 `ORDER BY` 决定 |

流式导出在后台任务里跑，有进度、能取消、失败能重试。取消或中途失败不会留下一份
看上去完整的文件。

## ER 关系图

对象树头部的关系图按钮打开。整库的表都画出来，包括没有外键的；每张
列出全部字段与类型，外键按具体字段连线。

- 拖动空白处平移，双指或滚轮缩放；「适应窗口」「实际大小」；卡片可以自由拖动，
  「复位所有卡片」还原布局。
- **搜索**表名或列名：把不相干的压暗，图的形状不变。
- **过滤**：按 Schema、「以这张表为中心」走 N 跳关系、「只看有关联的表」。过滤直接把
  表拿掉并重新排布，表很多时用它。
- 「导出」为 SVG（矢量）、PNG 或 PDF。
- 在本应用里执行过 DDL 后会自动刷新；别处改过结构点「重新读取」。

想先看看效果，可以导入仓库里的示例 schema（`examples/`，用法见 README）。

## 查询历史

侧边栏底部的「查询历史」。每次执行都会记下来，不论成功、失败、取消还是超时：
时间、连接、数据库、语句、耗时、状态和影响行数。

- 按文字（在 SQL、命名和标签里找）、连接、状态、日期范围筛选；「只看收藏」；
  「只看慢查询」。
- 每条可以收藏、命名、打标签，复制 SQL，或「在新标签里打开」。
- **历史里不存查询结果**。语句里的口令（`IDENTIFIED BY`、`PASSWORD =` 之类）在
  写入前就被换成 `'***'`，照原样重跑会失败，界面上会提示。

保留规则在「设置 → 查询历史保留」：默认保留 30 天、最多 500 条。收藏、命名或打过
标签的不按时间过期；跑得比「慢查询阈值」（默认 1000 毫秒）还久的也不按时间淘汰。

## 设置

侧边栏底部的「设置」：

- **外观**：数据网格的行高（紧凑 / 标准 / 宽松），两张网格同时生效。
- **危险语句确认**：每个环境从哪一级开始确认，见[危险语句确认](#危险语句确认)。
- **查询历史保留**：保留期（7、30、90、365 天或不按时间删）、条数上限（100 到
  2000）、慢查询阈值。调小上限立刻生效，删掉的不可恢复。

主题（浅色 / 深色 / 跟随系统）和语言（中文 / English / 跟随系统）在侧边栏底部
直接切换，命令面板里也有。

## 常见问题

**对象树是空的，写着「暂无数据库对象」。**
MySQL 连接没填「数据库名称」时会直接提示；填了还是空，确认这个账号能看到那个库。
在别处刚建的表点刷新。

**MySQL 连不上，报 TLS 相关的错。**
新建 MySQL 连接默认「要求 TLS」（很多云数据库要求加密）。本地没开 TLS 的 MySQL，
把 TLS 模式改成「禁用」或「优先使用 TLS」。

**测试连接一直转，最后超时。**
先点「网络诊断」。如果它说「端口接受了连接又立刻断开」，看看本机是不是开着 TUN
模式的代理。

**表数据的操作列写着「只读」，没有编辑按钮。**
这张表没有主键或非空唯一键，或者读不到它的索引信息。表格上方的说明写着是哪一种，
见[为什么这张表只读](#为什么这张表只读)。

**提交时报「第 N 项没有恰好影响一行」。**
那一行在你读到之后被别人改了或删了。整批已经回滚，改动都还在队列里；刷新后再改。

**查询结果只有 1000 行。**
那是工具栏上的「结果上限」。调大，或者用导出里的「完整结果」。

**Linux 上勾「保存密码」报打不开钥匙串。**
装一个 Secret Service（如 gnome-keyring）并解锁，然后重启 DataOmni；或者不保存
密码，每次连接时输入。

**重跑历史里的语句失败了，提示口令被替换。**
历史写入前会把语句里的口令换成 `'***'`，这类语句要自己补上口令再执行。
