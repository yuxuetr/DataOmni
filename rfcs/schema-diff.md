# 两个库的结构比对与同步脚本（D3）

2026-11-05。状态：用户已确认（脚本只放进编辑器、删表默认不勾、其余照本文）。任务在 `TODOs.md`「1.x」的 D3。

## 1. 要回答的问题

「开发库改了几张表，生产库要跟上，差哪些、该跑什么」。同类产品（Navicat 的结构同步、DBeaver 的
Compare/Migrate）都有这一项。用户 2026-11-05 点名要做。

产出两样东西：

1. **差异报告**：哪些表、列、索引、外键只在一边有，或两边不一样。
2. **同步脚本**：在目标库上跑完，目标的结构就和源一样。只在**同一方言**之间生成。

要新写的只有：**两份目录之间的对齐与比较**、外键的加与删（两条语句）、把各段按次序拼成一份脚本、
**同时开第二个连接**、界面。

## 3. 比什么

比对的单位是**一个连接当前的库**，即 ER 图画的那个范围。

| 对象 | 比 | 同步脚本 |
| --- | --- | --- |
| 表 | 有无 | 只在源里的：`CREATE TABLE`（§2 那一套）。只在目标里的：`DROP TABLE`，**默认不勾** |
| 列 | 有无、类型、可空、默认值 | `buildTableDdl`。它拒绝的照原样列出来 |
| 主键 | 列与次序 | **只报告**。`buildTableDdl` 本来就不改主键：要先验证现有数据唯一、还要看谁引用它 |
| 唯一约束与普通索引 | 按**定义**比：列、次序、是否唯一。名字不同不算差异 | 删目标多的，建源里多的 |
| 外键 | 按定义比：列 → 被引用的表与列。名字不同不算差异 | 删目标多的，加源里多的。SQLite 与 DuckDB 不能事后加删外键，列为「做不到」 |
| 视图、触发器、存储过程、序列 | **只列名字**：哪些只在一边有 | 不生成 |
| 检查约束、注释、排序规则、分区、表选项、外键的删除规则 | 不比 | — |

不比的那几项写在报告结尾，避免「没报差异」被读成「完全一样」。外键的删除规则不比，是因为 ER 图的
外键查询现在不读它（`ErLink` 没有这一项）。等有人要再给五家的查询都加上。

### 3.1 怎么对齐

- **表**：同名即同一张表，不区分大小写。PostgreSQL 与 SQL Server 比较时要连 schema 一起比；
  如果两边各只有一个 schema，就忽略 schema 名，这样 `dev` 和 `prod` 两个 schema 也能互比。
- **列**：同名即同一列。**不猜改名**：源里的 `email` 和目标里的 `mail` 报成「删一列、加一列」，
  脚本里删列那一条照 `DdlImpact` 列进「会丢的数据」。猜对了省一步，猜错了丢一列数据，不值。

### 3.2 什么算「类型不同」

两边方言相同，所以比目录给的原文，只抹去大小写与空白。只有一处已知的假差异要处理：MySQL 8.0.19 起
`int(11)` 不再带显示宽度，和 5.7 比会处处报差异，所以比之前去掉整数类型的显示宽度。

其余假差异（比如默认值在不同服务端版本上写法不同）不预先猜，靠 §6 的往返验收找出来。找到一种就补一种，
每种配一条测试。

### 3.3 跨方言

只出报告，不出脚本。报告比表与列的有无、可空，类型只并排列出、不判相同与否。如果拿代码生成的
`logicalType` 去判，`varchar(255)` 对 `nvarchar(255)` 这类组合判对判错都说不清，不如原样给人看。

## 4. 脚本的次序

1. 删外键（目标里多的，以及要改的列上挂着的）。
2. 删索引。
3. 建表，按依赖排序。
4. 改列，一张表一段 `buildTableDdl`。
5. 建索引。
6. 加外键。
7. 删表（勾了才有）。

先删外键、最后加外键，是为了改列和建表时不被引用关系挡住。

新建的表有两点要注意：

- 库自己给的建表原文（`SHOW CREATE TABLE`、`DBMS_METADATA`）里已经带着外键和索引，第 5、6 步不再为这些表重复生成。
  它们引用的表要先建，靠的是依赖排序。
- 原文里可能带着源的 schema 名，Oracle 的 `DBMS_METADATA` 会写出 `"OWNER"."T"`。源和目标 schema 名不同时，
  照原样执行就会建到源的 schema 里。所以这种情况下改用从目录重建（`reconstructTableDdl` 那一套，
  PG 与 SQL Server 本来就走它）。做不到重建的方言，在报告里列为「做不到」，不拼一条建错地方的语句。

每一段都带上它的 `refusals` 与 `impacts`，合成一份 `DdlPlan` 交给预览框。预览框加一个按表分组的
差异列表，每项可以取消勾选，脚本跟着重算。

## 5. 界面与两个连接

**入口**：ER 图的菜单里加「与另一个库比对…」。当前连接就是**目标**，再选一个连接作为**源**，
可以对调方向。也可以选同一台服务器上的另一个库或 schema，这时还是开第二个连接，只是库名不同。

**第二个连接**：现在全应用只有一个活动连接（`queryStore.database`）。比对时另开一个只读的句柄，
步骤与连接时相同：先 `test_connection` 读钥匙串、建隧道、拿到连接串，再 `openDatabase`。只读目录，
读完就关。有一个坑：两份配置可能算出同一个连接串（`sharesRegisteredPool` 处理的就是这种情况），
这时关第二个句柄会把活动连接的池子一起关掉。所以与活动连接同串时直接借用活动句柄，不关。

**执行**：不另写执行路径。目标是当前连接时，「在编辑器中打开」把脚本放进一个新的 SQL 标签，由用户
自己跑，执行时照常走环境确认（生产库按策略弹框）。目标是另一个连接时，只能复制或保存成文件。
这样「对生产库执行」这件事只有一个入口，比对功能不会成为绕过确认的旁路。

**支持的库**：PostgreSQL（含 CockroachDB、openGauss）、MySQL（含 MariaDB、TiDB、OceanBase）、SQLite、
SQL Server、Oracle、DuckDB，也就是能做结构编辑的那几家。ClickHouse 不支持，理由与它不能结构编辑
相同（`CreatableDialect`）。`buildTableDdl` 拿到的服务端版本选项（`renamesApart` 等）按**目标**的
版本取。

## 6. 怎么验

1. **单测**：纯函数 `diffCatalogs(source, target, dialect)` 输出差异，`buildSyncScript(diff, options)`
   输出 `DdlPlan`。语料按 `codegenFixture` 的写法造一对「源 / 目标」，覆盖：多表、少表、多列、少列、
   改类型、改可空、改默认值、索引同定义不同名（不报差异）、外键增删、主键不同（只报告）、
   SQLite 改类型（拒绝）、MySQL 显示宽度（不报差异）、两边各一个 schema 但名字不同。
2. **往返（主要的验收门）**：在真库上建两份不同的结构 A、B，比对出「把 B 改成 A」的脚本，在 B 上
   执行，**再比一次必须为空**。这一条能抓出假差异、语句次序错、方言写法错，单测抓不到这些。
   做成 `scripts/schema-diff-verify.sh`：SQLite 每次都跑；PostgreSQL、MySQL、SQL Server 在设置了
   冒烟测试那几个连接串环境变量时跑（规矩同 `database_smoke.rs`，连接串只在 shell 里传）。
   反向验证：故意让生成器漏掉一种差异（比如不生成改默认值），确认第二次比对不为空、脚本退出码非零。
3. **真应用**：两个 SQLite 文件，从 ER 图发起比对，预览，在编辑器里打开并执行，再比一次为空。

Oracle 与 DuckDB 的往返没有现成的测试库，只靠单测，写进「没验到的」。

## 7. 这一版不做

| 不做 | 理由 | 什么时候重估 |
| --- | --- | --- |
| 猜列与表的改名 | 猜错就丢数据 | 有人拿出「改名被报成删加」的真实场景 |
| 改主键 | `buildTableDdl` 不做，理由见那里 | 同结构编辑 |
| 比较数据 | 另一件事（数据比对），规模也不同 | 用户要 |
| 视图、触发器、过程的定义比较与同步 | 定义原文跨版本写法飘，比较噪音大，要先有往返验收的数据 | 往返门稳定之后有人要 |
| 一键在目标库直接执行 | 见 §5「执行」 | 不重估：这是安全取舍 |
| 存成快照文件、和快照比 | 能用两个连接比就够了 | 有人要「和上个版本的结构比」 |
